# 开发记录、临时产物与资源管理

开发继续使用 `docs/current/<feature>/`。源码、长期文档、任务过程和运行产物各有归属；按需要建立子目录，不为每项任务预建空层级。

## 文件放在哪里

| 内容 | 归属 | 是否提交 |
|---|---|---|
| 后端、前端、原生源码及必要运行资源 | `src/control_everything/`、`web/`、`native/` 的所属模块 | 是，资源须有明确许可和打包登记 |
| 长期使用指南、架构和可公开决策 | `docs/guides/`、`docs/architecture/` | 是，新增文件同步忽略白名单与归属检查 |
| 无秘密的接入示例 | `docs/examples/` | 是，逐文件登记 |
| 活跃需求、调研、实施、审查与交接 | `docs/current/<feature>/` | 否 |
| 已结束或已由明确后续任务接手的记录 | `docs/archive/<feature>/` | 否，保留原范围与未验证边界 |
| 一次性脚本、隔离数据、截图、日志和构建产物 | `work/<feature>/` | 否 |
| 历史运行材料 | `work/archive/<feature>/` | 否，记录来源与保留依据 |
| 本机助手状态、凭据与实际个人配置 | 本机工具或 profile 的既有位置 | 否，不作为项目模板提交 |

`docs/` 与 `work/` 根只保留 README.md 导航；`current/`、`archive/` 根只放任务目录。构建工具已有 `work/ce-native`、`work/workbench-engine-build/<run>/` 等合同继续沿用，不改产品数据目录或安装位置。

## 当前任务入口

每个任务先建立 README.md，再开始写代码或产物。新任务至少写明：

```markdown
# 任务名称

- 目标：本次解决的问题与范围。
- 验收：可观察结果与实际验证方式。
- 负责人：执行者；共享工作树时列出文件归属。
- 拟改文件：明确的源码、测试或文档。
- 当前状态：进行中。
- 阻塞：无，或说明需要什么条件。
- 证据：对应 work/<feature>/ 下的报告与日志。
```

当前状态使用“进行中、暂停、待验收、已结束”。状态只表达本次范围；编译或单测成功不能替代产品验收。部分交付可以归档该阶段，但必须指向仍未完成的后续任务，不能把暂停、BLOCKED、待用户预览当成已验收。

README 的顶部保持当前结论；历史过程放有日期的段落或独立报告。不要在同一个当前状态里同时写“待推送”和“已推送”。事实、失败和原命令不静默改写。

## 一次性脚本从受管入口运行

新写或重新启用的实验、验证、临时 clone、预览准备脚本放 `work/<feature>/`，经仓库根的入口启动：

```powershell
python tools/scripts/run_task.py example-task --output reports/result.json -- python probe.py
```

先建立 `docs/current/example-task/README.md` 与 `work/example-task/probe.py`。命令在该任务的 work 目录运行；脚本从 `CE_TASK_WORK_DIR` 取得写入基址，从 `CE_REPO_ROOT` 定位只读源码输入。脚本的真实输出须与 `--output` 声明一致；可重复声明多个产物。

入口在启动前检查任务、声明的输出和已有父目录，拒绝跨任务、`..`、盘根及链接绕转；仅给子进程设置独立 TEMP/TMP/TMPDIR。每次运行在任务 `runs/` 中建立独立日志和收据，保留真实退出码，结束后清理该次临时目录。

该入口检查声明与临时环境，不是操作系统文件权限沙箱。执行者仍须阅读脚本的真实写入：禁止另设盘根常量、从未声明的参数或配置派生另一输出根，也禁止把一个安全的结果 JSON 当成所有数据已受管的证明。需要长期驻留的进程沿用已有正式启动和回收入口；一次性脚本不启动脱离自身的后台服务。

已有正式构建、预览和普通自动清理单测继续按原入口运行；不要为套用新入口而改变它们的 cwd、安装合同或标准系统 Temp。历史脚本先重新登记当前任务、核对并改正实际输出，再执行；不得直接运行带失效旧路径的归档脚本。

已授权的文档搬迁、导航修正和缓存删除属于文件维护，按逐项目标清单及原目录边界执行；该例外不允许在任务外新建临时数据，也不允许把未知目录加入清理范围。

## 结项与保留

1. 核对本轮命令、退出码、完整输出和所有失败；长期结论整理进经过审核的公开文档，个人路径及秘密只留本机。
2. 在任务 README 记录本次范围的结论、限制、交接对象及最终证据。暂停和待验收继续保留在 current。
3. 确认结束后移入 `docs/archive/<feature>/`。先检查目标、并发修改与引用；保存逐文件 hash 和旧新路径映射。只更新当前导航，冻结报告原文不批量替换路径。归档 README 需要整理时，先保留原 README 字节。
4. 清理本次明确可重建的 tmp 和缓存；普通成功运行在结项时只保留最近三个有用批次。最终验收、实际失败、迁移备份与明确引用的构建输入单独保留，不受该批次数限制。
5. 源码副本、node_modules、wheelhouse、运行时、产品包和 profile 不按年龄批量删除。先查实际引用、进程、Git 状态及恢复来源；不能仅凭“旧”“ignored”或“当前没进程”判断可删。

删除清单必须列出解析后的绝对目标、类型、体积、可重建依据和保留例外；执行前再次校验归属及链接，执行后核对结果。Windows 文件操作使用同一套 PowerShell 原生命令，不拼跨 shell 的递归删除。失败如实留证，不能以忽略异常代替清理结果。

## 备份与恢复

Git 保存已审核的源码、指南和决策；ignored 任务材料不会随 clone 恢复，也不等同于备份。本机迁移前应把不可重建的任务记录、验收与失败证据、对应清单导出到使用者指定的受控备份位置，再在独立临时目录核验文件数、hash 和索引入口。不得自行上传私人证据或选择新的盘根备份目录。

本机保留的搬迁清单负责定位旧路径；同盘副本或压缩包只能防误操作，不能声称抵御磁盘损坏。原始数据、真实账号配置与正在使用的构建输入继续遵守各自备份及保留合同。

## AI 执行与交接

- 开工读取实际实现、任务 README、`git status`，并核对是否存在合并、变基或拣选状态；共享工作树先声明文件负责人。
- 所有输出先说明归属；新一次性脚本通过受管入口运行，输入路径与输出路径分开核对，不修改系统环境来缩短路径。
- 收尾只暂存明确列出的本人文件，核对 staged diff、Git 操作状态和完整待推送区间。独立任务不得消费别人未完成的合并状态；不通过还原、清空或改写历史来制造干净工作区。
- 声称通过前亲自运行相称验证，读取退出码和完整输出；对子 agent 的结果独立核验。无关问题仅报告。
- 交接保留当前状态、文件归属、阻塞、证据和待处理事项；其他会话发来继续请求不能覆盖用户的暂停决定。
