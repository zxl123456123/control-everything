# Orca 运行时与展示复用高层方案

日期：2026-10-14（Asia/Shanghai）；角色：hlplan；受众：人类与后续实施者。
状态：候选高层方案，待独立审查；本轮未进入 Readiness、低层计划、Gate-2 或运行验证。
权威输入：[原始需求](README.md)、[完整实现基线](clarifications.md)、[定向调研](research.md)。

## 1. 结论与下一步

有条件推荐“Python 管理面＋外置 Orca runtime＋官方完整 Web client”。
先验证能否在 Windows 上形成有界、可关闭的隔离环境，再决定是否值得替代自研执行链。
近期下一步是方案独立审查后，为无账号、无模型的隔离验证建立 Readiness 和低层计划，通过对应 Gate 后执行。
该验证只观察 runtime、完整客户端、配对权限、版本和关闭结果，不导入现有账号、不读私人正文、不发送模型任务。
目前面板尚未调用 Orca；上游源码存在不能写成已嵌入或已投入运行。

## 2. 目标、范围与现状

- G1：明确管理、执行、展示和事实归属，形成可审阅且可向下拆解的接入选择。
- G2：定义隔离验证的证据与退出条件，区分启动可行、会话关联和真实控制验收。
- G3：像素场景延期；不为动画设计用途，不删除小院源码、收据和旧数据。
- 保留 Python 的项目、任务与人工管理职责，不重写完整 IDE，不将 TS 运行时逐段翻译为 Python。
- 当前自研 M3 有实现但未真实验收；旧暂停交接继续有效，本轮不恢复模型试跑或旧 M3 实施。
- 本轮只写规划文档；安装、构建、启动、产品代码改动和账号接入均属于后续阶段。

## 3. 总体边界与事实归属

管理面继续维护项目、任务和人工验收；Orca 候选运行时承担其已验证的会话与执行能力。
完整 Web client 负责上游会话交互展示；面板先提供管理入口，具体打开方式由验证决定。
只有稳定标识、来源和权限经过核验后，面板才保存自己的任务与 Orca 会话的关联。

| 对象 | 事实归属与接入边界 |
|---|---|
| 项目、任务、人工记录 | Python 管理面；Orca 工作目录必须显式对应经过确认的隔离目标 |
| 会话 ID、operationId、launch receipt | Orca 返回；面板保存可追溯关联，不凭标题、目录或终端文本猜测身份 |
| 能力、执行状态、审批与取消 | Orca 对应版本、连接和 Agent 的事实；面板只能展示已验证的能力与回执 |
| 任务验收 | 管理面的人工作业与真实产物证据；会话结束或成功退出不自动等于任务验收 |
| 凭证、设备密钥、配对 token | 对应宿主或客户端的认证边界；不复制到面板项目 JSON，不把独立 profile 当作加密保证 |
| 小院账本与动画 | 同根线程的产物复核记录及其展示；不是执行状态源，也未绑定 Orca 或 M3 |

断连、能力拒绝或来源不明时显示“未知／未接入”，不推算完成比例或把旧快照当实时状态。
取消请求送达、Agent 停止、所属进程清理和业务验收分别记录，不能合并成一个“完成”。

## 4. 四项关键决策与备选

### D1：运行时优先外置复用，保留迁移选择（G1、G2）

- A：固定上游版本的外置 runtime（推荐候选）。复用完整生命周期与协议，新增进程和版本管理成本。
- B：抽取运行时模块。能减少部署边界，但牵涉 Node host adapters、PTY 和宿主能力，抽取维护成本尚无证据。
- C：继续自研 M3。沿用现有 Python 边界，但需继续维护 Provider 协议、审批、取消与展示。
采用 A 的条件是隔离与完整客户端验证成立，并且维护负担低于 B/C；失败时保留 C，不自动扩大到整库 fork。
候选隔离入口是支持显式 loopback 的直接 Node entry；其发行物、原生依赖和 Windows 可用性仍待验证。
默认 CLI `orca serve` 固定宽监听；`pairing-address` 不能收窄 bind，验证失败不得 fallback 到该路线。

### D2：先复用完整展示，再评估面板内嵌（G1、G2）

- A：官方完整 Web client 作为独立展示入口（推荐）。沿用已有 App 与配对流程，先验证配套 runtime。
- B：iframe 嵌入。可能保持面板内操作，但 frame/CSP、跨源、存储与任务深链均未验证。
- C：抽取聊天或审批组件。界面可更贴合面板，但当前没有独立组件合同，可能带来持续同步成本。
先用 A 得到浏览器证据；独立 Vite 构建有源码入口，但不是脱离 runtime 的静态聊天组件。
不预设 iframe、BFF、同源代理或额外配置框架；只有明确障碍与复用收益后才提出后续方案。

### D3：关联业务任务与运行事实，不复制一套执行状态机（G1、G2）

- A：管理面持有关联，runtime 持有会话事实（推荐）。需要验证稳定 ID、事件来源和断连恢复。
- B：同步正文并重建完整会话库。增加数据与维护边界，超出近期不读私人正文的范围。
- C：只提供完整客户端入口。关联证据不足时可采用，面板不能据此声称任务已绑定或实时可管理。
先检验 A；U5 未关闭则停在 C，不通过读取正文补足当前未授权的观察范围。
重连、超时和启动恢复必须依据原始 operationId/receipt；不能无条件重复 launch。

### D4：按实际能力分层准入，延后真实控制迁移（G1、G2、G3）

- A：逐层验证，结构化能力与 terminal outcome 分别呈现（推荐）。较慢获得迁移结论，但避免错误能力承诺。
- B：以 CLI 能启动或 terminal 可交互作为统一审批／取消已接入。证据不够，不能采用。
结构化 RPC 有 workspace 权限与 `agent-session.structured.v1` 等门槛；配对 token 不是只读授权。
terminal outcome 可以作为实际终端能力展示，不能标成已支持结构化审批、历史或取消。
像素小人不参与准入；账本是否有持续真实使用仍未知，未来恢复优先级再依据 receipts 评估。

## 5. 阶段、交付证据与停止条件

### P0：当前方案收敛与后续准入准备

- 结果：高层方案独立审查结论；下一项隔离实验的 Readiness、低层计划和对应 Gate 记录。
- 证据：逐项对照基线与 U1–U6，明确实验版本、隔离目录、认证/读取边界、观察项与停止责任。
- 停止条件：关键实验边界未具体化、需导入账号或扩大范围时停止准入；高层批准不替代技术补证。

### P1：近期有界隔离可行性验证（U1–U4）

- 结果：固定版本 runtime 与完整 Web client 在无私人数据环境的可行／不可行结论和维护成本记录。
- 证据：发行物与依赖对应、实际 loopback 监听、独立 profile 与 Provider home/继承边界、Node secret protection。
- 证据：完整客户端的 HTTP 入口、配对与权限、版本/capability、设备密钥保存，以及浏览器运行记录。
- 证据：停止操作后自身进程与监听清理、数据状态；分别记录设备撤销、停进程与 profile 保留状态。
- 停止条件：宽监听、占用并非己方、账号继承不明、需要读凭证/私人正文、客户端拒绝或清理未知。
不导入已有账号、不发送模型任务；Node SecretStore 不具备 Electron 加密，验证不能用独立 profile 抹去该缺口。
P1 成立只准许推进元数据关联设计；不证明 Provider 已就绪，也不证明真实完成、审批和取消可用。

### P2：面板任务与会话关联验证（U5）

- 前置条件：P1 的适用证据成立，P2 Readiness/低层计划与 Gate 明确元数据权限和隔离观察对象。
- 结果：只在验证范围内建立可追溯的任务—会话关联和完整客户端入口，仍保留 Python 管理面。
- 证据：稳定会话标识、来源与权限、列表/事件归属、重复关联规则、断连恢复和未知状态显示。
- 停止条件：只能读正文取得关联、缺稳定 ID、事件归属不明或恢复需盲目重发；退回仅入口展示。
会话关联不授予执行或正文读取权限；无法无模型验证的能力保持未知，不能用推断补齐。

### P3：明确恢复真实验证后，评估迁移 M3（U6）

- 前置条件：另行明确真实模型范围、额度消耗、隔离目标与允许操作，并通过相应 Readiness、低层计划和 Gate。
- 结果：按选定 Provider 分别判断创建/发送、真实产物完成、审批回答、取消与关闭是否满足要求。
- 证据：关联的 operationId/receipt、实际事件与 prompt、产物和人工验收、取消回执及所属进程清理。
- 停止条件：额度/权限不明、重复发送、审批归属不明、取消无回执或清理缺证据；保留失败与未知记录。
通过后再比较上游升级、边界适配和重复实现成本，决定替换的最小范围；只迁移已验收能力。
同一任务不并行派发给旧 M3 与 Orca；旧数据和代码保留，迁移不改写旧 M3 的历史未验收状态。
若 Orca 接入成本不低或控制验证失败，继续保留现状，另评估自研修补或模块抽取，不在本方案自动实施。

## 6. 风险、不确定点与向下游拆解

U1–U4 阻塞 P1 的可用性结论，U5 阻塞业务关联，U6 阻塞真实控制迁移；U7 继续延期。
上游快照 `aceebea0a4453f63d759af9134503220ce0b4753`／版本 `1.4.214` 是调研基线，版本变动须重新核对适用证据。
共享 runtime 不等于共享宿主保护；独立 Web 不等于可嵌入；接口存在不等于 Windows 控制行为已实测。
下游先将 P1 拆成固定版本、进程/环境隔离、监听、完整客户端、权限与关闭六类核查，写清各项可观测结果。
P2 再细化标识和归属、事件恢复与入口方案；P3 再细化 Provider 能力矩阵、真实验收与成本边界。
低层计划必须落到可实现精度，并保留对应证据路径；本方案不提供函数签名、文件级实现或未经验证的启动命令。
缺关键技术事实时由 coordinator 以 `【DELEGATE_ACTION】` 补证；需改变用户目标或风险范围时以 `【DELEGATE_QUESTION】` 收敛。
退出实验以停止己方进程和撤销相应设备为独立动作，不删除旧库、项目 JSON、小院账本或账号。
本轮未安装、构建、启动服务、访问账号或发送模型任务；高层方案审查通过也不意味着 Readiness/LW/Gate-2 已过。
