## 头脑风暴决策

核心问题：同时使用多种 coding agent、多个项目和终端，项目/待办/额度/AI新闻分散，希望在桌面、浏览器和手机尺寸里有一个可信的工作入口。

1. 把项目、任务、agent会话和额度分成独立事实，不把文件mtime、进程存活或巡游动画当工作进度。
2. 保留今天已有项目进度、待办、启动器和旧会话/小院页面，优先以增量模块交付可运行的新工作台；不做无证据的整库重写。
3. 参考 Orca 的 provider能力区分、任务与会话关联、主机/工作区边界；不照搬其完整IDE、远程中继和所有依赖。
4. 架构须覆盖长期多agent控制；本轮交付可用的管理面（真实项目/会话发现、本地任务及负责人/状态、可验证的额度来源、AI资讯），对尚不能执行的能力清晰标注，不以卡片冒充agent接入。
5. Codex额度优先官方app-server。本地CLI为0.118.0，生成schema有account/rateLimits/read、没有account/usage/read；不自动升级CLI。不读取凭证到前端，不启动turn来查额度，不兑换额度/购买credits。日用量缺来源时保持未知或明确人工记录。
6. Grok网页订阅、Grok CLI credits、xAI API消费必须区分。没有已验证读取来源就显示未接入，提供原服务入口和可选人工记录，绝不默认100%或0费用。
7. 采用同一响应式Web界面作为桌面和浏览器的基础；原生包装与手机远程访问要独立说明交付程度，不把窄屏截图称为手机已连通。可用本机桌面窗口入口；不自动开放监听地址、防火墙或中继。

以上为coordinator在用户授权内作出的实现决策，不伪称用户逐项选择过技术栈。

## 完整实现基线

### 1. 目标锁

- G1：交付架构方案，含实际代码现状、Orca源码/官方证据、替代方案取舍和从现有实现迁移路线；主要设计均追溯到用户目标。
- G2：交付可运行工作台，将已登记项目、待办、跨provider任务管理与真实能力/会话入口、额度来源、AI资讯组织为可操作页面；使用真实本地数据，无伪造活跃/完成/额度数据。
- G3：实际核验桌面和360/390px布局及关键交互，提供真实页面截图；保留现有数据、会话观察和小院能力。

### 2. 反目标

- 不造一个仅有静态示例数字的漂亮首页；未知、失败和旧数据必须可见。
- 不把工作台变成完整IDE、微服务平台、任意命令执行器或自动付费agent调度器；不为未来所有provider创建空泛插件框架。
- 不删除既有进度或覆盖用户手工数据，不改旧交付/审查记录，不未经证据更换全栈。

### 3. 风险边界

- 本机可信用户、loopback服务，沿用严格Host/Origin/CSRF。手机远程需要单独身份与网络边界，暂不公开监听。
- 新任务跟踪为工作台事实，手工标记必须标明来源；执行回执仅在真实provider返回后产生。未实现的dispatch、cancel、approve不可显示为可用。
- 原有固定启动入口可以复用，但测试不得启动实验或真实agent推理；真实会话消息正文非本轮必要数据。
- 新增本地数据持久化只要求SQLite常规事务/错误明确返回，保留原文件；不发明跨服务事务/自动迁移已有库。
- 不自动重启不属于本轮的运行服务。开发预览可用明确的独立loopback端口；失败不暗中换端口或接管现有进程。

### 4. 验证责任

- impl负责代码语法、业务单测、纯fixture协议/存储测试，保存命令、退出码及所有失败；不能用fixture宣称实际外部接入。
- coordinator负责真实本地启动、浏览器桌面/窄屏交互、截图、官方只读额度探测和公共资讯抓取；不得触发付费任务或现存启动器的有影响动作。
- fresh reviewer审实际最终diff、基线/方案和证据；任何修改后重新验证并重新审查。证据不足只能写未验证。
- 基线root已执行202项unittest，退出0；已有pydantic IncompleteFieldDefinitionWarning保持可见。初次git status失败是无Git环境事实。
