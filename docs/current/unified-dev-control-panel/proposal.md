# 统一开发控制面板：用途与分批建设建议

2026-10-03。讨论稿，依据本轮本机代码调研、官方文档和用户已确认的目标：**日常项目开发效率优先，3D 和 Jev 用来辅助理解与决策**。不是已批准的高层/低层实现方案；尚未改动既有产品。

## 1. 这个面板应帮你完成什么

以项目作为共同上下文，关联 Codex 聊天、WezTerm/Zellij 终端、任务、分支、服务、日志、需求、决策和产物。它应帮助你回答：

1. 现在各项目在做什么，哪些任务在等我处理？
2. 某次失败发生在哪个步骤，证据在哪里，下一步应检查什么？
3. 这轮代码改动影响了哪些模块，与原需求和已确认的决策有什么关系？
4. 模型或渲染资产是哪一版、如何产生、是否通过验收？
5. Jev 的建议有没有减少人工分类与定位时间，实际错误有哪些？

“巨大”适合指覆盖范围和可展开的工作空间。默认首页应集中显示需要处理的事件，完整信息通过视图和详情展开；不必同时播放所有图形和动画。

## 3. 四种视图，共用一个项目上下文

### 工作与监控：每天默认进入

左侧项目列表，中央任务/会话，右侧当前选中事件的证据，底部迭代时间线。跨项目总览优先列待人工处理、失败和长时间无进展的任务。

建议覆盖的信号：

- 会话：工具来源、任务主题、工作目录、运行/等待输入/待审批/空闲/未知、最后事件时间。
- 代码：分支、改动文件、提交、构建和测试结果；多个聊天共享同一目录时提示关联，不把同时工作自动判为冲突。
- 服务：在线状态、具体请求错误、工作流执行失败、日志入口和版本。
- 主机：CPU、内存、磁盘、网络、GPU及显存；本地与远端分别标注。
- 产物：构建包、文档、模型、渲染图/视频、源文件和生成任务。
- AI用量：有明确来源时显示请求延迟、token与实际费用；Codex账户级额度不能倒推出某个聊天的费用。

每项显示来源、采集时间与覆盖范围。连接正常、任务在运行、业务结果正确是三种状态。没有接入的项目显示未知/未接入；历史快照明确标注时间。可用服务链接先直接打开，未必需要重建所有监控图表。

### 架构与脑图：理解和回溯

架构图回答“系统怎样工作”，对话脑图回答“为什么做这次改动”。两者关联但保留不同对象：

- 架构：真实模块、配置、请求/任务阶段、接口和数据流。
- 脑图：需求 → 问题 → 方案 → 已确认决策 → 任务 → 变更 → 验证 → 提交。

节点可回到对应聊天消息、文件、测试结果或提交。自动整理得到的关系是候选关系；已确认决策来自真实来源，不由模型凭空生成。先人工/半自动整理关键节点，再评估自动关联。

动态效果对应实际信息：沿边粒子代表被记录的事件，节点脉冲代表执行，事件结束后停止；错误要附文字和具体来源。教学动画、历史重放、实时观察分别标记。

### 3D与C4D：模型、空间检查与资产生产

3D环绕适合真实模型、拆分结构、相机、材质与资产版本检查；如果项目本身没有3D对象，可把空间图用于架构讲解和演示，再通过节点回到2D详细证据。默认工作页无需持续占用GPU旋转。

建议从一个真实交付物开始，例如项目架构的演示资产、产品交互模型或研究中的结构动画。Cinema 4D的作用是制作这些资产及可复现的场景，而浏览器承担轻量预览和关联项目任务。

### Jev决策实验：检验开发收益

本次最匹配的工具是 [TypeSafe Jev](https://docs.typesafe.ai/introduction)。它针对状态和明确问题返回Choice/Score/Noul判断；不生成代码、模型、脑图文字或自然语言推理链。公开技能/SDK不等于开源模型权重。[官方技能仓库](https://github.com/typesafe-ai/skills)

一个可优先验证的候选实验是**失败任务分诊**：输入经整理的失败摘要与必要环境事实，在网络、依赖、资源、逻辑错误、信息不足等明确类别中选择，展示模型分布，再记录人工纠正和最终定位。尚未收集实际失败案例，先核对这类问题在你的工作中是否足够常见，再决定是否作为首个实验。

动态页面按实际事件展示：

`输入快照 → 明确候选 → 概率分布 → 程序/人工最后决定 → 工具执行回执 → 验证结果`

它可以用概率柱、选中分支、执行路径和完成状态展示；3D可作为同一事件的空间表达，不能把这种动画称为Jev内部思考。模型概率/confidence和任务成功率分别显示。

同一批真实样本比较现有规则、Jev和必要时已有LLM：分类错误、人工纠正比例、定位耗时、请求延迟和费用。包含“信息不足”选项，记录顺序重排后答案是否变化。精确阈值、费用计算、权限和进程退出用确定规则处理。

官方已承认中文等CJK精度、选项顺序、精确计算和长无关上下文的限制；当前能核实的是托管API。本轮没有实际调用，尚无本项目收益测量。详见 [research_jev.md](research_jev.md)。

## 4. Cinema 4D怎么从建模到渲染接入

先核对本机版本、实际MCP设置与工具列表。Maxon当前官方文档已经提供内置MCP，列出Modeling、Transforms、Animation、MoGraph、Node Graphs和Rendering等工具组，并提到Codex客户端；应优先核对这条现成入口。[MCP说明](https://help.maxon.net/c4d/2026/en-us/Content/html/MCPADAPTERPREFS.html)、[工具组](https://help.maxon.net/c4d/en-us/Content/html/MCPADAPTERPREFS-MCPADAPTERPREFS_GROUP_TOOLSET.html)

网页路径和正文有版本差异，不能据此断言本机支持。这个MCP仅运行于完整GUI应用；无人值守渲染需独立核对c4dpy/Commandline入口。[FAQ](https://help.maxon.net/c4d/en-us/Content/html/MCP_Server_FAQ.html)

一个具体的起步流程：

1. 选定交付物和验收：交互模型、架构演示还是最终视频；确定源文件、输出尺寸和预览用途。
2. 在单独场景中建模，给对象命名并对应项目资产；先完成简单几何与层级。
3. 设置材质、灯光、相机和必要的轨道运动；涉及MoGraph/节点材质时记录参数。
4. 先低分辨率预览，检查结构、相机遮挡、标签和材质，再渲染最终产物。
5. 保存.c4d源文件与所需贴图；输出轻量GLB用于网页环绕，同时保留实际渲染图/视频。
6. 面板关联源版本、生成任务、日志、输出文件和验收状态。编辑操作由实际C4D工具执行，最终结果依靠文件与视觉检查确认。

GLB的材料、灯光和部分动画存在导出限制，不能承诺原样保留Redshift成片。网页交互与最终成片分别验收。[glTF导出](https://help.maxon.net/c4d/2026/en-us/Content/html/FGLTFEXPORTER.html)

没有GUI MCP的安装版本，可以再评估官方Python SDK/脚本；后台渲染使用官方命令行入口。只有并发渲染确有需要时才增加队列/农场；安装、许可、可用GPU和权限尚未在本轮验证。

## 5. 推荐的建设顺序及验收

| 批次 | 做什么 | 用什么证明有用 |
| --- | --- | --- |
| 接入核对 | 明确项目清单、连接实例、只读接口、监控覆盖；旧面板可跳转 | 各数据都能回到来源；采集不会resume/打断其它开发会话 |
| 日常工作台 | 项目、会话、待处理项、变更和已有监控入口联动 | 从一个项目找到对应聊天/终端/报错，无需在多个窗口反复辨认 |
| 架构与脑图 | 需求/决策/改动/验证关系与真实架构节点关联 | 随便选一次已结束迭代，都能说明改了什么、为什么、如何验证 |
| Jev分诊实验 | 一种常见失败场景，基线与真实结果对照 | 定位时间或人工分类负担有改善，同时误分类可见；不达标则保持实验用途 |
| C4D与3D资产 | 一个真实场景的建模、预览、渲染、版本关联 | 产生可使用的模型/视频，能回溯源文件和生成任务 |

首批用一两个真实开发案例验收，例如定位某个工作流失败、恢复某次迭代的需求与验证上下文。先记录原流程的定位耗时和窗口切换次数，再比较统一入口，作为后续扩展的依据。

这是一组范围建议，具体批次仍需要形成并确认实施基线，再按当前coordinator的意图、风险与既有状态路由；跨工具架构和关键接入事实仍未明确时走正式方案与评审。优先做只读聚合与原工具跳转；不提前重建全部应用、复制所有代码、引入大型遥测基础设施或自动执行任意命令。

## 6. 本轮交付与验证边界

- 3份调研报告、目标确认记录、本建议稿和交互布局讨论稿。
- 布局可切换项目与四种视图、点击证据节点、调整占位模型环绕角度；不是实时监控，未调用Jev，未制作实际C4D资产。
- 首次Playwright浏览器检查因默认配套浏览器不存在失败（exit1）；改用本机Edge后检查通过（exit0），覆盖项目联动、视图、证据详情、环绕和1024/360/320宽度，pageerror为0。
- Maxon网页重抓与全文find出现无匹配/超时；行业调研使用同一官方URL正文抓取核对，失败历史保留在报告。
- Workbench8765本轮连接拒绝；未启动/重启已有服务。没有复跑其它项目测试，没有判断其它聊天任务已完成。
- 当前目录不是Git仓库，本轮没有commit/push。
