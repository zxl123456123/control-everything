# 通用项目管理与开发进度：增量架构方案

日期：2026-10-14；角色：architect；受众：共享。
状态：待独立 Readiness 评审。本文是当前兼容增量，不改写旧冻结架构、计划和验收对象。

将项目登记、人工进度和任务记录作为统一管理的基础；目录负责定位，进度来源负责提供观察。默认每个用户得到独立的空工作台，有文档的项目可以选择来源，没有工作流的项目仍然可以管理。此次不把旧执行系统或个人终端环境一同迁移。

## 1. 输入、目标与非目标

权威输入为本目录 `clarifications.md` 的十节完整实现基线、用户原话、`research.md` 与 `research-industry.md`。下述设计选择属于用户已授权 agent 承接的普通单机架构决定，不能表述为用户逐字段选择。

### 可验收目标

- G1：其他本机用户通过页面登记项目、修改名称和目录、归档项目、管理任务，不需要修改源码、Git 或特定工作流。目录搬迁和多个工作目录保留同一项目 ID。已有管理数据通过明确导入保留原 ID 和记录。
- G2：页面分别显示人工进度、任务统计与文档观察。有限来源覆盖 workflow-for-coding、普通文本和版本化 JSON；无配置、缺失、无可识别内容、错误、实际 0 可区分。PASS 不自动完成项目或覆盖人工事实。
- G3：新配置、项目、目录、人工进度与历史在重新读取后有效。关键 Codex 元数据读取使用同一显式配置；空 profile 不访问个人 SSH、启动器、garden 或执行 owner。交付可操作页面、隔离存储/HTTP/浏览器证据和 fresh Review(Impl)。

### 非目标和持续约束

- 不重写 Python、SQLite、原生页面和 loopback 安全合同；不引入 Web 框架、前端框架、任意代码插件或通用工作流解释器。
- 不自动合并同仓库项目，不依赖 Git 自动发现，不估算文档完成百分比，不根据 Agent 活跃或文档日期宣告完成。
- 不迁移旧执行、审批、事件、garden 或私人会话正文，不恢复 M3 费用试跑，不安装、配对或启动 Orca，不接管已有服务。
- 不初始化 Git，不覆盖本轮之外未知改动。现有真实文件和服务不作为测试环境。

## 2. 现状与方案总体思路

研究确认注册列表本身并不限定六个项目，但默认注册文件和部分元数据来源包含个人环境假设。旧项目只有一个 root；空注册被拒绝；人工状态写入可能过滤孤立 ID；工作台和旧进度路由各有读取链；生产启动构造执行服务时会写 recovery 账本。仅替换一个路径不能达到 G1–G3。

本批在现有单体中增加三个职责边界：

| 边界 | 权威职责 | 与旧系统的关系 |
|---|---|---|
| 用户 profile | 本用户数据目录、显式元数据来源配置、管理数据和兼容导入清单 | 共享源码不再充当所有人的默认登记数据；不自动读取源码旁的个人文件 |
| 项目管理 | 稳定 ID、名称、归档、目录绑定、人工进度及历史、任务和用量记录 | 保留现有任务与人工用量语义；新增项目/进度数据，不搬迁执行账本 |
| 进度观察 | 按项目选择有限的只读来源，输出带来源和读取状态的观察 | 旧工作流只是一个预设；不成为人工状态和任务状态的写入主体 |

项目目录和会话样本之间仍然使用明确的目录归属规则。仅显式配置的 Codex 元数据源可提供样本；其不足、不可用和覆盖范围必须保留，不声明“当前正在开发”。现有工具能力目录可以保留说明，但个人启动器与终端操作不能在新 profile 中成为默认可执行功能。

## 3. 四项关键决策与备选

### D1：每用户 profile + SQLite 管理权威

备选 A 是继续让源码旁 JSON/SQLite 同时充当所有用户配置；分发时会携带个人登记，无法保证空默认。备选 B 是 profile 配置用小型版本化 JSON、管理数据用 SQLite，保留现有事务和查询方式。备选 C 是新增服务/插件框架或全面重写，代价超过本批目标。

采用 B。profile 配置只记录宿主级来源设置；项目、目录、进度、历史、任务、人工用量和导入清单属于管理库。配置写入使用有界校验和原子替换，管理记录使用 SQLite 事务；不新增用户目录库依赖。profile 的缺失字段采用明确默认，未知版本或损坏配置报错，不自动回落到个人文件。

profile 目录优先级：显式 `--data-dir`，其次专用环境变量，最后当前用户的标准数据目录。Windows 默认位于当前用户 LocalAppData 的 SessionPanel 子目录；环境缺失时依据当前用户 home 推导，产品中不得写入用户名。其它宿主只提供合理路径回退，不因未受测而声称跨平台验收。

默认首次启动创建空管理库，Codex 元数据来源未配置；不存在默认个人 SSH、Grok 目录扫描、启动器、garden 或 ExecutionService。管理页面可直接使用。用户在页面配置 Codex 元数据库路径后才允许只读六字段元数据查询；禁用时全部相关路由返回未配置状态，不读取默认库。

### D2：稳定项目 ID + 显式多个目录，保留唯一执行 root 合同

备选 A 是目录、远程仓库地址或工作流文件名派生项目 ID，搬迁或同仓库多个项目会破坏关联。备选 B 是一次登记生成稳定 ID，目录是可修改绑定，已有 ID 导入时原样保留。备选 C 是自动扫描所有磁盘/Git 工作树再合并，超出明确登记范围。

采用 B，并借鉴 [VS Code 多根工作区](https://code.visualstudio.com/docs/editing/workspaces/multi-root-workspaces) 的显式目录登记。一个项目拥有一个主目录和有限数量的附加目录；保存时不得重复绑定同一规范化词法目录，不允许两个活动项目直接重复登记同一目录。目录缺失允许保存并显示不可用，用户可先登记后恢复路径。

主目录是既有执行合同唯一 root；附加目录只参与只读会话观察。主目录更改不更改 ID、不删任务或历史；任何执行上下文若仍由旧服务持有，仍应按原 root 身份和 context_hash 校验，不因多目录观察而获得新的执行准入。portable profile 本批不装配执行服务；未来独立接入必须维持此合同。

目录归属按规范化绝对路径匹配。嵌套目录同时匹配多个项目时，观察取最长匹配目录；等长冲突作为歧义，不自动绑定。手工给任务关联会话仍必须检查所选项目的显式目录，且不能继承执行授权。词法观察不被升级为物理 symlink/junction 安全证明。

### D3：人工事实、任务统计、来源观察并列

备选 A 是将文档 PASS、文件日期或任务完成比例折算为项目百分比，会把评审通过和最终完成混淆。备选 B 是三类事实独立展示，由人工进度表达整体状态；任务提供数量/状态分布；来源提供阶段与文本或结构化观察。备选 C 是 AI 解释任意工作流，无法给出本批有界、稳定的判定合同。

采用 B。每个项目最多选择一个文档来源，人工进度始终可用。不存在人工记录时整体进度未知；人工设置 0 是有效值；任务没有条目时显示没有任务，不能生成整体百分比。任务做完不自动完成项目，文档 JSON 的 percent 也只作为来源报告值。

有限内置来源如下：

| 来源 | 输入与输出 | 完成语义 |
|---|---|---|
| 未配置 | 人工记录和任务仍可用，文档观察标记未配置 | 不推断完成 |
| workflow-for-coding 预设 | 选择项目目录，观察其 docs/current 下有限的直接子目录及 README/progress 文本，保留阶段和摘要 | PASS/完成词保留为文本，不按这些词过滤条目或改整体状态 |
| 通用文本 | 用户指定某个已绑定目录内的相对文本路径；展示有限摘要，可识别明确的阶段行 | 无明确结构也可以显示有来源的原文摘要，不猜百分比 |
| 版本化 JSON | 用户指定相对 JSON 路径，读取有限的状态、阶段、百分比、说明和时间字段 | 字段经校验后只作为来源观察，不覆盖人工或任务 |

结构化 JSON 提供可分享的编码形式，字段、版本、可选性和数值范围由 LW 唯一冻结；它不是其他工作流必须采用的协议。普通文本来源用于兼容不愿改造文档的项目。预设来源用文件日期排序观察，只表示文件新旧。

读取类别至少区分 not_configured、missing、unrecognized、error 和 available。JSON 损坏/字段不合法属于 error；空文本或预设无可识别记录属于 unrecognized；available 中 percent=0 保持 0。人工历史只在用户实际修改记录时追加，页面刷新和文档读取不得制造历史事件。

### D4：显式只读导入，拒绝覆盖目的 profile

备选 A 是自动迁移源码旁文件和全 SQLite，会意外复制个人环境、执行提示/事件，且可能接管运行。备选 B 是用户明确选旧数据目录，读取管理领域全部记录，一次导入空目的 profile；源文件不变。备选 C 是让旧文件永久作为新写入权威，保留原先过滤、路径和并发缺陷。

采用 B。空 profile 可在页面发起导入，来源目录必须显式提供，不默认填写开发者路径。页面先解释导入范围和目的 profile 路径；成功返回逐类完整计数、备份位置和未导入领域，失败返回可操作原因。非空 profile 或已导入 profile 拒绝再次导入，用户可使用另一个空 data-dir，避免设计冲突合并器。

仅导入项目、人工进度、旧待办、全部工作台任务和全部人工用量记录。旧 500/100 展示查询不得作为输入；读取只针对管理表和已知字段，不查询 execution、审批、事件、garden 或私人正文，不备份整个源 SQLite。已有 ID、状态、关联、创建/修改时间保留；缺失的来源时间标注未知，不能伪造历史。

旧 registry 有效且相关记录能完整校验时才提交一个目的库事务。孤立 project_id 的任务与人工进度**保留原 ID**，不按登记过滤、不生成带虚假目录的项目：任务显示“未登记项目”，允许修改原任务状态/说明或明确重新分配到有效项目；人工孤立记录在兼容记录区可查看和编辑，或由用户以原 ID 恢复项目登记后正常呈现。新任务只能选择活动项目；新建项目默认生成 ID，恢复孤立登记的受限入口只接受待恢复的现有 ID。

语法损坏、记录非法、重复 ID、未知不兼容 schema 或超过明示读取预算时，整体拒绝导入并保留源和目的原状；不得默默过滤坏项、截断总量或只导入前 N 条。LW 冻结预算与错误定位，不以未知真实数据量保证迁移成功。

目的 profile 导入前生成自身管理库的一致备份及必要配置快照，来源仍原地保留。撤销采用备份恢复到**另一个空 profile**再切换 data-dir；不在线覆盖已导入 profile，不删除导入后的新记录。恢复入口拒绝非空目的目录。用户始终可以切回原 profile，两个目录保留。原执行账本明确显示“保留在旧目录、未导入，本 profile 执行不可用”，不能宣称新页面已承接执行历史。

## 4. 模块职责、数据流与可用入口

### 启动与宿主来源

profile 装配是生产启动的唯一管理配置入口；旧测试的显式替身和无 workspace 的兼容 handler 合同可以保留。正式默认启动不构造旧执行、garden、远端 Claude 或启动器扫描。不能用改变常量后仍走旧装配的方式声称默认空隔离。

profile 管理页面提供新增/编辑/归档项目、主目录/附加目录、文档来源、人工状态/百分比/说明、人工历史、Codex 元数据路径和显式旧目录导入。目录以绝对路径文字输入，文件源以受限相对路径输入；不引入系统文件选择器或磁盘搜索。归档可恢复，记录保留；归档项目任务仍可查看和更新已有状态，但不作为新任务分配目标。

旧进度页读取同一 profile 的项目/人工数据，写入沿用同一管理权威。旧 Codex 分页和 workspace 会话样本使用同一配置读取器；未配置、禁用、缺失和 schema 不匹配均有明确状态。个人 desk/launch/远端/garden/执行入口在 portable profile 中返回明确不可用，页面不呈现可执行的个人操作。仅提供能力说明不应触发发现或启动副作用。

原命令的默认行为因此有意义变化：默认进入新 profile，而不是源码旁旧数据。README 必须给出默认启动、指定 data-dir、导入原目录、配置元数据、恢复备份/切换 profile 的可执行说明；不能依赖用户从空卡片猜测旧记录去向。原数据和已运行旧服务本轮不移动、不重启；若旧服务占用端口，用户需为新实例明确选另一个 loopback 端口，产品不得自动终止已有进程。

### 管理写入

项目写入校验 ID、名称、有限目录绑定和来源配置；普通修改采用管理库事务。人工记录与其历史同事务；项目归档、重绑不删其它表。所有写路由保持现有 Host/Origin/client/CSRF 和有界 JSON 请求体入口；不能为了多路径绕过长度预算，LW 应选与当前 4096-byte 合同相容的字段上限或明确一致的有界扩展。

管理数据具有明确的 schema/profile 版本。新版本迁移只能针对当前 profile 的管理表，保留任务/用量语义；未知未来版本拒绝打开，不静默重建空库。旧 execution 表既不成为新库必备对象，也不因新服务启动被 recovery。

### 进度读取

来源绑定必须指向当前项目明确目录中的文件或预设位置。读取前规范化并校验实际解析路径仍在选定绑定内；符号链接/junction 将文件导向目录之外时返回 error，不访问出界目标。来源只读且有单文件、枚举条数、摘要和总读取预算；预设仅观察有限直接子目录，不递归遍历项目。

文件/目录不存在、访问失败、超预算、非法 JSON 分别进入读取状态与诊断；不得吞为人工 0 或空成功。错误只影响该项目来源，不能阻断全部管理任务或人工数据。项目重新绑定目录后，同一相对来源跟随新绑定；若被引用的附加目录被删，保存应拒绝未处理的来源绑定，不能猜测另一个目录。

## 5. U1–U6 收敛、风险与验证要求

| 研究 U 点 | 本方案结论 | LW/验收必须证明 |
|---|---|---|
| U1：默认 profile 与导入 | 当前用户目录、默认空、显式只读导入空目的库 | 优先级、空启动、配置重读、源与目的不被失败/导入覆盖 |
| U2：权威存储与孤立记录 | SQLite 管理权威；孤立原 ID 保留并可操作；完整事务导入 | 超展示上限全量、非法整体拒绝、孤立编辑/恢复、归档不删记录 |
| U3：多目录与执行 | 明确目录、嵌套最长观察、唯一主 root；本批执行不装配 | 相邻 worktree 观察、冲突规则、重绑 ID 稳定，旧执行 root/context 测试不被放宽 |
| U4：来源协议和事实冲突 | 人工/任务/文档独立；四类来源；有界路径和状态 | 真 0、未知、missing/error/unrecognized、PASS 仍观察且不自动完成、越界不读取 |
| U5：空 profile 副作用 | 不构造 SSH、launcher、garden、执行 owner | 启动/关键路由使用禁止调用替身，页面只发允许请求；无真实服务接管 |
| U6：同配置覆盖读取链 | workspace/progress/Codex分页消费同一来源配置，garden无profile读取 | 同一替身路径的逐路由证明；禁用后无默认用户名回退 |

主要风险：

- 旧数据非法或真实量超预算：拒绝整批，报告定位和预算，原数据保留；不能把 fixture 导入通过称为真实个人数据已迁移。
- 启动默认改变导致误以为数据消失：空态展示 profile 路径与导入入口，README 给出旧目录导入和另端口预览命令。
- 来源读预算不足或解析识别不全：保留状态与有限摘要，不写整体进度；用户可以转为文本/JSON或人工管理。
- 多目录被误当执行准入：观察与唯一 root 明确分开，执行维持禁用和旧合同回归；新能力不宣称 Agent/Orca 已兼容。
- 管理库与 profile 配置不是同一事务：只允许有界独立配置更新；失败要报错，不通过同时写两者实现隐含原子性。导入只更改管理库，不导入个人宿主配置。

以上 U 点在架构层已有选择，仍需 Readiness 与 LW 冻结可实现合同后才视为实施准备充分。

## 6. 向 LW 的拆解指引与交付里程碑

本增量保持一个需求主链，分开 backend 和 UI 工作包；实施按已评审 LW 冻结，不并入终端重构。

1. M1，profile 与管理模型：冻结配置优先级/版本、数据 schema、stable ID、目录与归档规则、孤立编辑/恢复、人工历史、旧任务和用量兼容；纯隔离存储证明重读和数据保留。
2. M2，来源与完整导入：冻结 JSON 编码示例、文本/预设读取合同、类别/预算/路径边界、全部管理记录导入、错误定位、目的备份与空 profile 恢复。测试不得查询 execution 私人表，必须包含大于500/100的 fixture 和非法批次原子拒绝。
3. M3，路由与装配：冻结所有 profile-aware GET/POST、旧入口不可用状态、同一 Codex 元数据配置、loopback/安全/有界 body、端口/data-dir 入口。用禁止调用替身证明默认不接触真实来源和 owner。这里 M3 是本 feature 的路由里程碑，不是旧 Agent 费用试跑 M3。
4. M4，可操作页面与文档：添加项目/目录/来源/人工进度/孤立记录/导入/元数据配置操作；新用户空态、错误草稿保留、来源状态与人工历史、归档保留可见。按桌面和320/375/768px检查布局、表单和失败行为。
5. M5，root 独立验收与 fresh Review(Impl)：隔离真实 SQLite/HTTP 与浏览器；禁止真实 SSH/额度/资讯/会话正文/模型调用。审最终文件差异、导入/读取/owner 边界和本轮完整输出，修订后重跑并 fresh review。

LW 必须精确落定但本方案不预置函数签名或文件级实现：数据字段/迁移、请求响应与错误、读取预算、SQL 全量选择列、孤立记录入口、备份清单/恢复校验、profile配置保存、脚本入口，以及 impl-safe 与 root-owned 测试划分。任何冲突基线或新不可逆范围先回报 coordinator；不把缺口留给实施随机选择。

## 7. 需求映射与官方参考取舍

| 需求 | 方案决策与最小交付 |
|---|---|
| G1：通用项目、不破坏关联 | D1 空 profile、D2稳定 ID/目录/归档、D4保留ID完整导入、孤立可操作 |
| G2：后续开发进度兼容 | D3人工/任务/观察、有限来源编码、历史、状态及有界读取 |
| G3：实际使用与关键来源配置 | 第4节页面/统一路由/装配、D1元数据配置、D4导入/恢复、M5根验证 |
| 风险边界/反目标 | 不装配执行/个人来源，不搬迁私密账本，无Git/框架重写，旧锁保留 |

采用 [platformdirs](https://platformdirs.readthedocs.io/en/latest/) 体现的每用户数据目录模式，使用宿主现有能力满足本次 Windows 入口，不为路径选择增加依赖。采用 [Python SQLite](https://docs.python.org/3.12/library/sqlite3.html) 的事务和目的库备份机制，不直接复制活跃源数据库主文件。暂不采用 [Git worktree 自动发现](https://git-scm.com/docs/git-worktree)：用户项目不保证有 Git，显式多目录已经覆盖当前需求。每项主要交付可追溯到上述 G1–G3 或明确风险合同，无新增无法映射的功能。
